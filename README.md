# Kudos Bot

## Описание проекта

Kudos Bot — корпоративный Telegram-бот, разработанный на Swift (Vapor 4), который помогает сотрудникам компании выражать благодарности коллегам и поддерживать позитивную командную культуру.

Бот работает полностью внутри Telegram, без веб-интерфейса, и обеспечивает:

- передачу благодарностей через удобное пошаговое меню,
- автоматические личные уведомления получателю,
- статистику и персональные данные:
  - просмотр количества отправленных и полученных благодарностей;
  - доступ к персональному экспорту своих благодарностей.
- экспорт данных в CSV:
  - администраторы могут выгружать полный экспорт по всем благодарностям;
  - каждый сотрудник может выгрузить персональный CSV:
    - отправленные благодарности,
    - полученные благодарности.
- строгий контроль доступа по списку сотрудников,
- встроенную админ-панель в Telegram для управления сотрудниками (добавление, деактивация, восстановление, полный экспорт),
- автоматические напоминания в рабочие чаты.

### Технологическая основа

- **Backend:** Swift + Vapor 4  
- **База данных:** PostgreSQL  
- **Архитектура:** feature-folder (BotMenu, Employees, Kudos, Reminders, Core)  
- **Контейнеризация:** Docker + Docker Compose  
- **Продакшен:** VPS (Ubuntu), деплой через Docker  
- **CI/CD:** GitHub Actions (тесты → сборка Docker-образа → деплой на сервер)  
- **Тестовая среда:** отдельная тестовая БД (`kudos_test`) + unit/integration тесты  


### Инструкции для ИИ и контрибьюторов

В репозитории есть файл `AGENTS.md` с правилами и ограничениями по архитектуре и стилю кода.  
Он нужен, чтобы ИИ-ассистенты и новые участники команды писали изменения в одном стиле и соблюдали принятые архитектурные договоренности.


## Основные возможности
Kudos Bot предоставляет набор функций, которые делают работу с благодарностями простой и удобной:

- Приветственное меню с кнопками, без необходимости ввода команд вручную.
- Передача благодарностей коллегам через пошаговый сценарий:
  - выбор сотрудника из постраничного каталога (по 10 человек на экран),
  - ввод благодарности (не менее 20 символов),
  - сохранение благодарности в базе данных.
- Личное уведомление получателю: после сохранения благодарности бот отправляет сотруднику в личные сообщения, от кого и за что ему сказали спасибо.
- Статистика и персональные данные:
  - просмотр количества отправленных и полученных благодарностей;
  - доступ к персональному экспорту своих благодарностей.
- Экспорт данных в CSV:
  - администраторы могут выгружать полный экспорт по всем благодарностям;
  - каждый сотрудник может выгрузить персональный CSV:
    - отправленные благодарности,
    - полученные благодарности.
- Хранение данных в PostgreSQL.
- Полная работа в Telegram-чате без веб-интерфейса.
- Поддержка нескольких администраторов с возможностью настройки через переменную окружения.
- Админ-панель в Telegram: добавление сотрудников, деактивация, восстановление из архива, полный экспорт благодарностей.

### BotMenu: сценарии и навигация

Ранее логика меню находилась в одном большом файле `BotMenuController.swift`.  
Теперь она разделена на несколько файлов-расширении по зонам ответственности: главный роутер (switch по `SessionState`), сценарии благодарности, статистика, админка (меню, сотрудники, привязка Telegram) и UI-хелперы (пагинация и списки).  

### Сессии и состояния диалога

Бот хранит состояние диалога (`SessionState`) в базе данных (таблица `sessions` через Fluent), а не в памяти.
Это позволяет не терять прогресс сценариев при перезапуске приложения или контейнера: после рестарта бот продолжает диалог с пользователем с последнего шага.

Хранимые поля включают текущее состояние и черновики (например выбранного сотрудника, страницу пагинации и т.д.).

### Каталог сотрудников

- Источник правды по сотрудникам — база данных, управляемая через админ-панель в Telegram.
- CSV-файл `Resources/SeedData/employees.csv` используется только для разового массового импорта и по умолчанию не применяется при старте.
- Чтобы включить импорт при старте, установите переменную окружения: `EMPLOYEES_CSV_IMPORT_ON_BOOT=1`.
- Режим импорта безопасный: CSV **только добавляет** отсутствующих сотрудников и **не** обновляет существующих и **не** деактивирует тех, кого нет в CSV.
- Каждая запись содержит:
  - ФИО сотрудника,
  - статус активности (Да/Нет),
  - Telegram ID для связи с ботом и отправки личных уведомлений о новых благодарностях.
- При передаче благодарности пользователь выбирает коллегу из постраничного каталога, что исключает необходимость ручного ввода `@username`.
- Если в базе есть сотрудники с одинаковым ФИО, бот автоматически добавляет к кнопкам суффикс `(N)` (например: `Иванов Иван (1)`, `Иванов Иван (2)`), чтобы выбор всегда был однозначным.

- В общем каталоге для выбора получателя показываются только сотрудники с заполненным `telegram_id`.
  Сотрудники без `telegram_id` не видны обычным пользователям, пока администратор не выполнит привязку.
  Это защищает от ситуации, когда в списке появляется человек, который еще не начал пользоваться ботом.

### Доступ и роли

- Бот обрабатывает только личные чаты в Telegram. Сообщения из групп и каналов игнорируются.
- Обычный пользователь получает доступ к боту только если:
  - его `telegram_id` есть в таблице `employees`,
  - флаг `is_active = true`.
- Если сотрудник не найден или неактивен, бот возвращает вежливое сообщение о том, что доступ ограничен.
- Администраторы всегда получают доступ, даже если их нет в `employees`. Админ определяется по:
  - `ADMIN_IDS` — список Telegram ID через запятую,
  - `ADMIN_USERNAMES` — список имён пользователей (без `@`) через запятую.

### Временные токены привязки (pending links)

Для безопасной привязки Telegram-аккаунтов используется механизм временных токенов.

Администратор может выдать сотруднику одноразовый код, который сотрудник отправляет боту в личном чате командой:

```
/link 123456
```

В админ-панели бот формирует эту команду в формате `code`, чтобы ее было удобно переслать и скопировать.

Код действует 6 часов. Просроченные или использованные записи автоматически очищаются планировщиком `PendingLinksScheduler` (периодическое обслуживание раз в 10 минут).

- При добавлении сотрудника администратор создает временную запись привязки (`pending_link`) с одноразовым токеном.
- Код (токен) передается сотруднику и используется для подтверждения привязки через команду "/link" в личном чате с ботом.
- Код действует 6 часов и автоматически удаляется планировщиком после истечения срока или использования.
- После успешной привязки Telegram:
  - `telegram_id` сохраняется в таблице `employees`,
  - временный токен удаляется и не может быть использован повторно.
- Механизм защищает от случайной или ошибочной привязки чужого Telegram-аккаунта.

### Авто-очистка непривязанных сотрудников

- Если сотрудник был создан, но `telegram_id` не привязан в течение 24 часов, бот автоматически удаляет такого сотрудника из таблицы `employees`.
- Перед удалением выполняется защита: если у сотрудника есть хотя бы одна запись в `kudos` (как отправитель или получатель), он не удаляется.
- Очистка запускается планировщиком раз в 10 минут вместе с обслуживанием `pending_links`.

### Связи и подсчёт статистики

- Благодарности хранятся с привязкой к сотрудникам через внешние ключи (`employee_id`, `from_employee_id`), а не просто к никам.
- Это обеспечивает корректный подсчёт статистики и экспорт данных даже при изменении никнеймов.
- Еще есть механика, чтобы при отсутствии Telegram ID используется резервный поиск по нику, но пока закомментировано в коде, чтобы не мешалось.
- Меню «Статистика» и персональные экспорты учитывают FK-связи между благодарностями и сотрудниками.

### Экспорт CSV

- Экспортированные данные содержат фамилию и имя отправителя / получателя, а не только их логины.
- Пример структуры CSV:

  ```
  Дата и время;От кого (логин);От кого (имя);Кому (имя);Причина
  ```

### Персональный экспорт для сотрудников

Каждый сотрудник может самостоятельно выгрузить свои данные через меню бота:

- «Статистика»
  - «Экспорт переданных» — CSV со всеми благодарностями, которые сотрудник отправил;
  - «Экспорт полученных» — CSV со всеми благодарностями, которые сотрудник получил.

Экспорт формируется автоматически и отправляется пользователю в виде файла прямо в Telegram.

### Напоминания о боте

Бот может периодически напоминать о себе в общем чате (например, в рабочей группе в Telegram).

За это отвечает модуль `Reminders`:

- **Тексты сообщений** берутся из файла `Resources/Reminders/messages.json` — это массив строк:

  ```json
  [
    "Не забывайте говорить спасибо коллегам 🙂",
    "Есть за что поблагодарить — самое время отправить спасибо в боте!",
    "Поддержите коллег добрым словом — откройте Kudos Bot и напишите благодарность."
  ]
  ```

- **Куда отправлять**:
  - переменная `REMINDER_CHAT_ID` — ID чата (группы или канала) в Telegram.

- **Когда отправлять**:
  - переменная `REMINDER_TIMES` — список времени в формате `HH:mm` через запятую.
  - Пример: `REMINDER_TIMES=10:00,15:30,19:00`.

Если `REMINDER_TIMES` не задана или пуста, напоминания просто не запускаются.

## Данные и структура базы

- PostgreSQL база данных запускается как сервис `db` в Docker Compose и использует volume для хранения данных.
- Таблица сотрудников содержит данные из CSV-семпла.
- Таблица благодарностей хранит информацию с FK-связями на сотрудников.
- Экспортированные CSV-файлы сохраняются в папке `exports/` на хост-машине (примонтировано как `./exports:/exports`).

## Тесты и тестовая среда

В проекте есть unit- и integration-тесты, которые проверяют:

- запуск приложения и выполнение миграций;
- работу репозитория сотрудников (поиск, пагинация);
- построение клавиатуры Telegram-меню (кнопки, разметка, роли);
- экспорт благодарностей в CSV (формат файла, BOM, разделители и содержимое).

### Структура

Тесты находятся в папке `Tests/AppTests`:

```
Tests/
└── AppTests/
        ├── AppTests.swift               # базовые проверки / healthcheck
        ├── EmployeesRepoTests.swift     # репозиторий сотрудников
        ├── KeyboardBuilderTests.swift   # построение клавиатуры бота
        └── CSVExporterTests.swift       # экспорт благодарностей в CSV
```

### Тестовая база данных локально

Для тестов используется отдельная база `kudos_test`, которая поднимается через `docker-compose.test.yml`:

```yaml
services:
  db_test:
    image: postgres:16-alpine
    ports:
      - "5433:5432"
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: kudos_test
```

Во время локальных тестов приложение запускается в окружении `.testing` и по умолчанию подключается к `postgresql://postgres:postgres@localhost:5433/kudos_test?sslmode=disable`.

Если задана переменная окружения `DATABASE_URL`, она имеет приоритет во всех режимах — это используется в CI.

### Запуск тестов локально

1. Поднять тестовую базу:

   ```bash
   docker compose -f docker-compose.test.yml up -d
   ```

2. Запустить тесты:

   ```bash
   swift test
   ```

### Тесты в CI/CD (GitHub Actions)

В `.github/workflows/deploy.yml` есть стадия **Run Unit & Integration Tests**:

- Runner: `ubuntu-22.04`.
- Swift устанавливается через `swift-actions/setup-swift@v1` с версией `5.9`.
- Поднимается сервис PostgreSQL с базой `kudos_test` на порту `5432`.
- Тесты запускаются командой `swift test`, при этом в окружении передаётся:

  ```bash
  DATABASE_URL=postgresql://postgres:postgres@localhost:5432/kudos_test?sslmode=disable
  ```

Если тесты не проходят, дальнейшие стадии (`build-and-push` и `deploy`) не выполняются, поэтому продакшен остается в прежнем стабильном состоянии.

- Пример `.env`:

  ```env
  BOT_TOKEN=ваш_токен_бота

  POSTGRES_DB=kudos
  POSTGRES_USER=postgres
  POSTGRES_PASSWORD=postgres
  POSTGRES_HOST=db
  POSTGRES_PORT=5432
  DATABASE_URL=postgresql://${POSTGRES_USER}:${POSTGRES_PASSWORD}@${POSTGRES_HOST}:${POSTGRES_PORT}/${POSTGRES_DB}?sslmode=disable

  ADMIN_IDS=12345678,12345678

  # Опционально: синхронизация сотрудников из CSV при старте (create-only)

  # EMPLOYEES_CSV_IMPORT_ON_BOOT=1
  ```

  ```bash

  docker compose -f docker-compose.prod.yml up -d
  ```

## Массовый импорт сотрудников на VPS (опционально)

Источник правды по сотрудникам — админ-панель в Telegram. CSV нужен только для разового массового добавления сотрудников (например, при первом запуске или при переносе базы).

### Вариант 1 (рекомендуется): через флаг импорта при старте

1. Подготовить CSV на сервере в `/apps/kudos-bot/Resources/SeedData/employees.csv` (формат как в `employees.template.csv`).
2. В `.env` временно добавить:

```env
EMPLOYEES_CSV_IMPORT_ON_BOOT=1
```

3. Перезапустить контейнер бота:

```bash
docker compose -f docker-compose.prod.yml up -d --no-deps --build kudos-bot
```

После импорта можно удалить переменную `EMPLOYEES_CSV_IMPORT_ON_BOOT`, чтобы при следующих рестартах импорт не выполнялся.


## Примечания

- Админ-панель является источником правды по сотрудникам. CSV используется только для разового импорта (create-only) и не деактивирует существующих сотрудников.
- Скрипт `Scripts/sync_employees.sql` можно использовать только как разовую утилиту миграции/починки и запускать осознанно (он может менять данные в БД).
- Для аварийного полного сброса (reset) можно использовать TRUNCATE, но это редко нужно.


## CI/CD и мониторинг

### CI/CD

- Автоматическая сборка и пуш Docker-образа в Docker Hub при пуше в ветку `main`.
- Теги образа: `latest` и SHA коммита.
- SSH-доступ к VPS для обновления контейнеров через `docker compose pull && docker compose up -d`.
- Пайплайн настроен в `.github/workflows/deploy.yml`.

### Мониторинг и healthcheck

- Эндпоинт `/health` — простой liveness-check (приложение поднято и отвечает HTTP).
- Эндпоинт `/healthz` — расширенный healthcheck для продового мониторинга.
  Проверяет:
  - доступность БД,
  - живость Telegram polling-loop.
- `/healthz` возвращает:
  - HTTP `200`, если БД и polling в норме;
  - HTTP `503`, если есть деградация.

- Примеры проверки:

  ```bash
  curl -i http://127.0.0.1:8080/health
  curl -i http://127.0.0.1:8080/healthz
  ```

- Настройка мониторинга (например, Uptime Kuma):

  - Тип: HTTP(s)
  - URL: `http://<IP_VPS>:8080/healthz`
  - Метод: GET
  - Интервал: 60 секунд
  - Таймаут: 10–15 секунд
  - Попытки: 2–3
  - Допустимые коды: только `200`
  - Авторизация: отсутствует

- Пороговые параметры (опционально через `.env`):

  ```env
  POLLING_STALE_SECONDS=120
  HEALTH_STARTUP_GRACE_SECONDS=120
  ```

- В `docker-compose.prod.yml` используется `autoheal`: контейнеры с label `autoheal=true`
  автоматически перезапускаются при `unhealthy`.

### Runbook при деградации

Если в Uptime Kuma монитор по `/healthz` ушел в DOWN, используйте короткий чек-лист:

1. Проверить статус контейнеров:

```bash
cd /apps/kudos-bot
docker compose -f docker-compose.prod.yml ps
```

2. Проверить текущий health:

```bash
curl -i http://127.0.0.1:8080/healthz
```

3. Посмотреть последние логи бота и autoheal:

```bash
docker logs --since=15m kudos-bot
docker logs --since=15m autoheal
```

4. Если `kudos-bot` нестабилен (частые ошибки polling/рестарты), выполнить ручной перезапуск:

```bash
docker compose -f docker-compose.prod.yml restart kudos-bot
```

5. Если недоступен весь VPS (SSH/команды не отвечают), локальный autoheal не сработает — нужен reboot через панель или API VPS-провайдера.

### Очистка данных в базе

Для полной очистки таблицы благодарностей и сброса счетчика ID используйте команду:

```bash
docker compose exec -it db \
  psql -U postgres -d kudos -c \
  "TRUNCATE TABLE public.kudos RESTART IDENTITY CASCADE;"
```

**Внимание:** эта операция необратима и удалит все записи.

## Ручное создание и управление бэкапами

Для сохранения состояния базы данных на VPS можно создать SQL‑бэкап вручную.

### Создание бэкапа

Выполнить команды на сервере в директории `/apps/kudos-bot`:

```bash
docker exec -t kudos-db \
  pg_dump -U postgres -d kudos \
  > kudos_backup_$(date +%F_%H-%M).sql
```

После выполнения в каталоге появится файл вида:

```
kudos_backup_2025-11-27_13-58.sql
```

### Рекомендации

- Хранить 1–2 последних бэкапа, старые файлы можно удалять.
- Для удаления старых бэкапов:

```bash
rm kudos_backup_2025-*.sql
```

### Восстановление из бэкапа

Чтобы восстановить базу:

```bash
docker cp backup.sql kudos-db:/backup.sql
docker exec -it kudos-db \
  psql -U postgres -d kudos -f /backup.sql
```

## Администрирование бота

С версии 2.0 в боте доступна полноценная админ-панель (кнопка «Админка» в меню «Спасибо»), которая позволяет управлять базой сотрудников прямо из Telegram.

Доступ к панели имеют пользователи, указанные в `ADMIN_IDS` или `ADMIN_USERNAMES`.

### Возможности админ-панели

#### 1. Добавление сотрудника
Пошаговый мастер добавления нового коллеги:

1. **Ввод ФИО**  
   Администратор вводит "Фамилия Имя".

2. **Создание временной привязки Telegram**  
   После ввода ФИО бот создает временную запись привязки (`pending_link`) с одноразовым токеном.  
   Администратор пересылает сотруднику команду привязки в виде `/link <код>`, а сотрудник отправляет ее боту в личном чате.  
   Токен имеет ограниченный срок жизни и используется только один раз.

3. **Завершение привязки**  
   После успешного выполнения команды `/link` бот сохраняет `telegram_id` (цифровой user_id) сотрудника и автоматически удаляет временный токен.

4. **Создание записи**  
   Сотрудник создается со статусом `is_active = false`. После успешной привязки Telegram через `/link` статус автоматически меняется на `is_active = true` и сотрудник получает доступ к боту.  
   Если привязка отменена до завершения, временная запись сотрудника удаляется.

#### 2. Деактивация (Увольнение)
Позволяет скрыть сотрудника из списков, не удаляя его данные (чтобы сохранить целостность статистики благодарностей).

- Администратор выбирает сотрудника из списка активных.
- После подтверждения статус меняется на `is_active = false`.
- Если есть дубли ФИО, в списке будут варианты с суффиксами `(N)` для точного выбора.

#### 3. Архив (Восстановление и удаление)
Позволяет управлять сотрудниками в архиве.

- Администратор просматривает список неактивных сотрудников.
- Выбирает нужного сотрудника и видит меню действий:
  - **✅ Восстановить** — возвращает сотрудника в штат (`is_active = true`).
  - **🗑 Полное удаление** — полностью удаляет сотрудника и все связанные благодарности (и как получателя, и как отправителя).
- При удалении бот показывает подтверждение и количество благодарностей, которые будут удалены.
- Если есть дубли ФИО, в списке будут варианты с суффиксами `(N)` для точного выбора.

#### 4. Полный экспорт
Кнопка «📊 Экспорт CSV» выгружает полный отчет по всем благодарностям за все время.
